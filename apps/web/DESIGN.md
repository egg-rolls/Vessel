# Vessel Web · DESIGN

> 视觉语言规则。适用于 `apps/web/**`。
> 本文只写判据与做法，不写实现进度。
> 与仓库 `AGENTS.md` 冲突时以仓库约定为准；可访问性与性能底线不可用“风格”换。

## 0. 一句话

**边界不是画出来的，是组织出来的。**
用底色分层，用阴影表达浮动，用间距表达分组，用颜色表达语义，用圆角表达可触。

现有 Linen 色系（暖中性底 + 黄铜强调）保留；本次重构换的是**表达层级的手段**，不是品牌色。

---

## 1. 五条理念（判据）

### 1.1 无 border

装饰性 1px 线一律移除。区域边界由**底色差**产生，分组由**间距**产生。
边框只在“没有它功能就坏”的地方保留（见 §3.2）。

判据：把这条线删掉，用户还能不能看出这是两个区域？
能 → 删线，用底色或间距；不能 → 说明底色差不够，先调底色，不是加线。

### 1.2 阴影塑层次

阴影只给**浮在内容之上的东西**：弹出层、悬浮 dock、模态、toast、可点击的离散卡片。
并排的内容块之间**不用阴影**，用间距和底色差。

判据：这个东西是否会在 z 轴上盖住别的内容？
会 → 给阴影；不会 → 不给。相邻卡片各带一层阴影 = 脏，不是层次。

### 1.3 gap 塑分割

分组靠距离，不靠线。同一组内 gap 小，组与组之间 gap 大。
列表项之间用 gap + hover 底色，不用 `border-bottom`。

判据：两个元素属于同一组吗？
属于 → 小 gap；不属于 → 大一档的 gap。永远不要用分隔线回答分组问题。

### 1.4 颜色区分内容

颜色是**语义**，不是装饰。每种底色回答一个问题：这是什么内容 / 什么状态。
同一屏内语义色不超过 3 种；强调色只用于可操作和当前焦点。

判据：换掉这个颜色，信息会不会丢？
不会 → 这个颜色是装饰，删掉；会 → 颜色必须同时有文字或图形兜底（色盲可用）。

### 1.5 圆角柔和尖锐

圆角表达“这是一个可触摸、可容纳的整体”。圆角随层级增大：
越靠近用户操作、越浮动的表面，圆角越大。

判据：这是一个独立的容器吗？
是 → 用它所在层级的圆角；只是文字或行内元素 → 不额外加圆角容器。

### 1.6 两条不可交易的底线

1. **可访问性**：焦点可见、对比度达标、颜色不单独承载信息、触控目标 ≥ 44px。
2. **性能**：不使用 `backdrop-filter`；不在大列表/滚动容器上动画 `box-shadow`。

## 2. 层级模型

层级 = **底色 + 阴影 + 间距 + 圆角** 四件事的组合，不是单独一个阴影。

| 层级 | 名称 | 用途 | 底色 | 阴影 | 圆角 |
|---|---|---|---|---|---|
| L0 | Canvas | 页面底色、正文流、助手消息 | `--bg` | 无 | 无 |
| L1 | Band | 应用栏、侧栏、底部栏等常驻骨架 | `--surface` | 无 | 无 |
| L2 | Card | 离散内容单元：run、工具卡、设置组、统计块 | `--surface-raised` | `--elev-1` | `--radius-md` |
| L3 | Floating | Composer dock、popover、菜单、待处理条 | `--surface-raised` | `--elev-2` | `--radius-lg` |
| L4 | Overlay | Modal、命令面板、Toast | `--surface-raised` | `--elev-4` | `--radius-xl` |

补充：

- **正文消息不是卡片**。助手消息、思考流、系统提示直接铺在 Canvas 上；只有用户消息用强调色 soft 底形成“气泡”。
- **一个区域最多一层表面**。禁止卡中卡再套阴影；嵌套内容用 `--surface-sunken` 底色或间距，不再加阴影。
- **L1 不用阴影**。应用栏/侧栏与画布的边界由底色差表达；滚动内容从下面穿过时也不加 blur。
- **L2 的阴影必须很轻**。它是“放在画布上的纸”，不是“浮在空中的窗”。
- **L3/L4 才允许明显阴影**。它们是真的盖住内容。

### 2.1 阴影阶梯

```css
--elev-1: 0 1px 2px rgba(35, 33, 29, 0.04), 0 4px 12px rgba(35, 33, 29, 0.05);
--elev-2: 0 2px 4px rgba(35, 33, 29, 0.05), 0 10px 28px rgba(35, 33, 29, 0.08);
--elev-3: 0 4px 8px rgba(35, 33, 29, 0.06), 0 18px 48px rgba(35, 33, 29, 0.12);
--elev-4: 0 8px 16px rgba(35, 33, 29, 0.08), 0 28px 72px rgba(35, 33, 29, 0.16);
--elev-inset: inset 0 1px 2px rgba(35, 33, 29, 0.05);
```

暗色主题整体加深，并提高不透明度（暗底上浅阴影几乎不可见）：

```css
--elev-1: 0 1px 2px rgba(0, 0, 0, 0.32), 0 4px 12px rgba(0, 0, 0, 0.22);
--elev-2: 0 2px 4px rgba(0, 0, 0, 0.36), 0 10px 28px rgba(0, 0, 0, 0.30);
--elev-3: 0 4px 8px rgba(0, 0, 0, 0.40), 0 18px 48px rgba(0, 0, 0, 0.42);
--elev-4: 0 8px 16px rgba(0, 0, 0, 0.45), 0 28px 72px rgba(0, 0, 0, 0.55);
--elev-inset: inset 0 1px 2px rgba(0, 0, 0, 0.35);
```

旧令牌 `--shadow` → `--elev-2`，`--shadow-lift` → `--elev-3`。迁移完成后删除旧名，不保留双轨。

### 2.2 什么时候允许阴影

| 允许 | 不允许 |
|---|---|
| 卡片、run、工具卡（L2） | 正文消息、思考流、系统提示 |
| 悬浮 Composer / dock（L3） | 应用栏、侧栏、底部导航（L1） |
| popover / 菜单（L3） | 列表项、表格行 |
| modal / palette / toast（L4） | 卡中卡的嵌套层 |
| 键盘焦点环（`--focus-ring`） | 纯装饰性的“立体感” |

## 3. 无边框规则

### 3.1 禁止

- `border: 1px solid var(--line)` 一类装饰性描边。
- `border-bottom` / `border-right` 做区域或列表分隔。
- `border-left: 2px` 做状态条（旧工具卡/notice 写法）。
- `border: 1px dashed` 做空态、上传区、占位。
- hover 时只改 `border-color` 作为唯一反馈。
- 用边框“补”两个相邻表面的边界；应改为底色差或间距。

### 3.2 唯一允许保留“线”的地方

1. **焦点环**：`:focus-visible` 必须可见，用 `box-shadow: var(--focus-ring)`，不是 `border`。
2. **强制色彩模式**：`@media (forced-colors: active)` 内恢复 `1px solid CanvasText`，否则系统高对比模式下表面会消失。
3. **原生控件内部**：浏览器/系统绘制、不可完全接管的几何线。
4. **滚动条**：用背景色 + `background-clip: padding-box` 形成视觉内边距，不加边框。
5. **分隔会破坏对齐的结构**：仅在“去掉线后表格/代码块无法阅读”时，用**极浅底色**代替线（`--surface-sunken`），仍不画线。

除此之外，任何 `border` 都需要在 PR 说明里写一句“为什么删不掉”。

### 3.3 边界替代公式

| 想要的边界 | 不要用 | 改用 |
|---|---|---|
| 两个区域分开 | 1px 线 | 底色差一档（`--bg` ↔ `--surface`） |
| 同组列表项分开 | 行分隔线 | `gap` + hover 底色 |
| 卡片从背景里出来 | 描边 | `--surface-raised` + `--elev-1` |
| 状态是失败/等待/成功 | 左侧色条 | 语义 soft 底 + 彩色圆点/图标 + 文本 |
| 输入框的边界 | 描边 | `--surface-sunken` 底；聚焦时焦点环 |
| 空态/占位 | 虚线框 | 低对比底色块 + 说明文字 |
| 表格行 | 横线 | 行高 + hover 底色；表头用底色区分 |

## 4. 间距（gap）

### 4.1 尺度

沿用 4px 基准：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 48`。

| 语义 | 值 | 用在哪 |
|---|---|---|
| `--space-1` | 4px | 图标与文字、徽标内部 |
| `--space-2` | 8px | 紧邻控件、chip 组 |
| `--space-3` | 12px | 卡片内行间距、列表项内 |
| `--space-4` | 16px | 卡片 padding、列表项之间 |
| `--space-5` | 20px | 卡片与卡片 |
| `--space-6` | 24px | 区块与区块 |
| `--space-8` | 32px | 页面大区块 |

### 4.2 分组用距离表达

- 同一组内：`--space-1` ~ `--space-3`。
- 组与组：至少是组内 gap 的 **2 倍**。
- 列表项：`--space-2` ~ `--space-3`；分组标题与内容用 `--space-4`。
- 页面左右 gutter：桌面 24–32，平板 16–20，手机 12。

**不要**用 margin 同时承担“间距”和“分组”两种含义；分组优先用父容器的 `gap`。

### 4.3 嵌套间距

- 外层 padding 决定内层圆角（见 §5.2）。
- 卡中卡只在“内容确实是一个独立对象”时出现；否则用内部间隔和底色分区。
- 移动端整体收紧一档：`--space-4` → `--space-3`，`--space-6` → `--space-4`；但触控目标不缩小。

## 5. 颜色

### 5.1 表面（回答“这是什么层”）

| 令牌 | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--bg` | `#f4f1ec` | `#171614` | Canvas |
| `--surface` | `#fbfaf7` | `#1f1d1a` | Band（应用栏/侧栏） |
| `--surface-raised` | `#fffdfa` | `#262320` | L2/L3/L4 表面 |
| `--surface-sunken` | `#efece5` | `#1a1917` | 输入井、代码块、次级信息区 |
| `--surface-deep` | `#e7e2d9` | `#151412` | 更深的分区（少用） |

浅色模式里“抬升 = 更亮”，暗色模式里“抬升 = 更亮一档”，两者方向一致。
相邻表面必须有可感知的亮度差；差值不够时用阴影补，不要用线补。

### 5.2 内容角色（回答“这是什么内容”）

| 内容 | 底色 | 文字 | 备注 |
|---|---|---|---|
| 用户消息 | `--accent-soft` | `--ink` | 不对称圆角，无描边 |
| 助手消息 | 透明 | `--ink` | 直接铺在 Canvas |
| 思考流 | 透明 | `--muted` | 可折叠；不用卡片 |
| 工具调用 | `--surface-sunken` | `--muted` | 折叠行；状态用圆点/图标 |
| 系统 notice | 语义 soft 底 | 语义色 | 失败/取消/排队各一色 |
| 权限 / 提问卡 | `--surface-raised` | `--ink` | L3，顶部用 accent 圆点标识 |
| 子 agent 记录 | `--surface-sunken` | `--muted` | 缩进 + 底色，不套第二层阴影 |

### 5.3 语义色

- 强调 `--accent`：当前项、可操作、焦点。不要用来表达成功。
- 成功 `--ok`、警告 `--warn`、危险 `--danger`、信息 `--info`：只表达状态。
- 每个语义色配一个 `-soft` 底色；状态块 = soft 底 + 同色文字/图标。
- **颜色不单独承载信息**：必须同时有文字、图标或形状（色盲与灰度屏可用）。
- 一屏内语义色不超过 3 种；多出来的通常是信息架构问题，不是配色问题。

### 5.4 对比度

- 正文文字与背景 ≥ 4.5:1；大字 ≥ 3:1。
- 图标、焦点环、控件的非文字边界 ≥ 3:1。
- `--faint` 只用于辅助信息，不用于正文。
- soft 底上的语义色文字必须重新核对对比度；不达标时加深文字色，不加深底色。

### 5.5 暗色

- 不用纯黑 `#000`；最低 `#151412`。
- 表面差异靠亮度阶梯，不靠描边。
- 阴影更深、更不透明；但不要把“能否分层”全押在阴影上。
- 语义 soft 底在暗色下提高不透明度（约 12%），避免糊成一片。

### 5.6 交互态

| 状态 | 表达 |
|---|---|
| hover | 背景加一层 ink 4%（暗色：white 6%），或语义色略深 |
| active/pressed | 背景再加一档（约 7–9%），或 `--elev-inset` |
| focus-visible | `--focus-ring`，必须可见 |
| selected/current | `--accent-soft` 底 + accent 文字/圆点；不是描边 |
| disabled | 降透明度 + 去掉 hover 变化；保持可读 |

## 6. 圆角

### 6.1 阶梯

| 令牌 | 值 | 用途 |
|---|---|---|
| `--radius-xs` | 6px | kbd、极小徽标 |
| `--radius-sm` | 8px | 输入井内的小块、代码行 |
| `--radius-md` | 12px | 默认卡片、工具卡、设置组 |
| `--radius-lg` | 16px | dock、popover、权限/提问卡 |
| `--radius-xl` | 20px | modal、命令面板 |
| `--radius-pill` | 999px | chip、badge、圆形按钮 |

### 6.2 嵌套圆角

内层圆角 = 外层圆角 − 外层 padding，最小值 4px。
例：外层 16、padding 8 → 内层 8；不要内层也写 16，会出现“胖角”。

### 6.3 例外

- 用户气泡：`16px 16px 4px 16px`（贴合发送方向），不是全圆。
- 全宽的 Band（应用栏/侧栏）不圆角；它们不是浮起的卡片。
- 表格/代码块的圆角只加在最外层容器；内部 td/pre 不单独圆角。

## 7. 组件规范

### 7.1 应用外壳

- 应用栏 / 侧栏：L1，纯底色，无下边框/右边框。
- 侧栏与主区靠 `--surface` ↔ `--bg` 的底色差分开。
- 应用栏不透明（不做 blur）；内容从下方滚过时也不改变。
- 移动端底部导航：L1 + 一条很轻的 `--elev-1` 表示浮起；不用上边框。

### 7.2 列表（会话、run、任务）

- 行与行之间：`gap`，无分隔线。
- 行本身：透明底 + 圆角；hover 加 ink 4%；当前项 `--accent-soft`。
- 元信息用 `--muted` / `--faint` 和更小字号，不靠描边区分。
- 列表容器不加卡片外框；列表就是内容本身。

### 7.3 会话流

- 消息之间 `--space-4`；不同角色之间 `--space-6`。
- 助手正文不包卡片；思考流可折叠，默认弱化。
- 工具调用是 L2 离散对象：`--surface-sunken` + `--radius-md`，无描边；状态用图标色。
- 失败 / 取消 / 排队：notice 块用语义 soft 底 + 圆点；不用左色条。
- 权限 / 提问卡：L3，`--surface-raised` + `--elev-2` + `--radius-lg`；标题区用 accent 圆点，不画分隔线。

### 7.4 Composer / dock

- L3：`--surface-raised` + `--elev-2` + `--radius-lg`。
- 输入区是 dock 内的 sunken 井（`--surface-sunken` + `--radius-md`），不描边。
- `:focus-within` 加 `--focus-ring`；不要靠加边框表示聚焦。
- 槽位（permission/ask）是唯一表面，卡内不再套第二层边框/背景。
- 停止、发送等操作按钮与输入区用 gap 分开，不用竖线。

### 7.5 卡片 / 面板 / 统计

- L2：`--surface-raised` + `--elev-1` + `--radius-md`。
- 卡片内部标题、正文、操作之间用 gap；不要用横线分区。
- 统计块是卡片的最简形式：数字用 mono，标签用 `--faint`。
- 页面级区块用 `--space-6` 分开；不要给每个区块都套外框。

### 7.6 表格

- 无行线、无列线。
- 表头：`--surface-sunken` 底 + `--faint` 小字；sticky 时保持不透明。
- 行 hover：ink 4%；当前行：`--accent-soft`。
- 小屏降列，不横向滚动到不可用。

### 7.7 表单

- 输入框：`--surface-sunken` 底 + `--radius-sm`，无描边；聚焦加焦点环。
- 错误：danger soft 底 + danger 文字，不靠红框。
- label 用 `--faint` 小字；描述用 `--muted`。
- 控件高度保持 32px 桌面 / 44px 触控。

### 7.8 浮层

- Modal / 命令面板：L4，`--elev-4` + `--radius-xl`；遮罩用 ink 55% 半透明，**不用 blur**。
- Popover / 菜单：L3，`--elev-3` + `--radius-lg`。
- Toast：L4，`--elev-3`，语义色 soft 底 + 图标。
- 浮层与触发元素之间用 gap，不用连线/箭头边框。

### 7.9 空态 / 错误 / 加载

- 空态：低对比底色块 + 说明 + 一个主操作；不用虚线框。
- 错误：danger soft 底 + 图标 + 可执行建议；不用红描边。
- 加载：骨架用 `--surface-sunken`；不要闪动边框。

## 8. 动效与反馈

- 时长：hover/按下 120ms，展开/收起 200ms，浮层进出 200ms。
- 缓动：`cubic-bezier(0.22, 0.61, 0.36, 1)`。
- 只动画 `background-color` / `color` / `opacity` / `transform`；**不**在大列表上动画 `box-shadow`。
- 抬升用 `translateY(-1px)` + 预置阴影，或伪元素透明度过渡。
- `prefers-reduced-motion: reduce` 时全部降为 0.001ms。
- 流式输出期间不触发会改变布局的动画。

## 9. 令牌落点

改 `apps/web/src/styles/tokens.css`：

- 新增：`--surface-raised`、`--surface-sunken`、`--surface-deep`、`--elev-1..4`、`--elev-inset`、`--radius-xs`、`--radius-xl`、`--radius-pill`、`--hover-tint`、`--press-tint`。
- 保留并收编：`--shadow` / `--shadow-lift` 先映射到 `--elev-2` / `--elev-3`，迁移结束后删除。
- 浅色/暗色两份必须同时定义；`[data-theme="dark"]` 与 `prefers-color-scheme` 两份不能漂移。
- 组件 CSS 只引用令牌，不写 hex、不写 `rgba()` 字面量（阴影令牌除外）。
- 不保留未使用的原子组件；当前只保留被实际调用的 `Button` / `AutoGrowTextarea`。业务样式留在各域 CSS。

## 10. 迁移映射（旧 → 新）

| 旧写法 | 新写法 |
|---|---|
| `.panel` / `.card` 的 `border: 1px solid var(--line)` | 删除；`--surface-raised` + `--elev-1` + `--radius-md` |
| `.appbar` / `.domain-nav` 的 border | 删除；靠 `--surface` ↔ `--bg` |
| `.data-table td` 的 `border-bottom` | 删除；行高 + hover 底色 |
| `.msg-toolcall` / `.stream-notice` 的 `border-left` | 删除；语义 soft 底 + 圆点/图标 |
| `.state-*` 的 `border: dashed` | 删除；低对比底色块 |

迁移时同步删除对应的 `border-color` 过渡；不要留下“无可见效果”的 transition。

## 11. 验收清单

每个改动提交前自检：

- [ ] 页面里还能看到装饰性 1px 线吗？（除 §3.2 例外）
- [ ] 每个阴影都能回答“它浮在谁上面”吗？
- [ ] 分组是否只靠 gap 就能读懂？把线全部隐藏后信息结构还成立吗？

- [ ] 触控目标 ≥ 44px？文本输入时键盘弹起后 dock 是否仍可见？

## 12. Not building（明确不做）

- 不做玻璃拟态 / 模糊背景 / 发光霓虹。
- 不做“每块内容都套一张卡”的卡片汤；正文与列表默认不套卡。
- 不引入第二套主题/皮肤；只维护 Linen 浅色 + 暗色。
- 不为了“看起来有层次”叠加多层阴影或渐变。
- 不用边框、色条、下划线作为主要信息编码。
- 不为视觉效果牺牲流式性能；不在滚动容器上做高成本滤镜或阴影动画。
- 不新增 UI 组件库依赖；沿用现有 React + CSS 令牌体系。

## 13. 实施顺序（约束）

1. **先令牌与原子层**：`tokens.css` → `base.css` → `ui.css`。这一步定义所有层级，后续不得各自造阴影/圆角。
2. **再外壳**：应用栏、侧栏、底部导航。外壳定调后，域内页面才有参照。
3. **再会话主路径**：会话列表 → 会话流 → 工具卡 → Composer / 权限 / 提问。
4. **最后其余域**：runs / observe / settings / workflows / integrations。
5. 每一层完成后做一次浅色 + 暗色 + 360/1440 的快照自检；不通过不进入下一层。

并行实施时，每个 N 只写自己获授权的文件；共享 CSS 文件在阶段 1 之前先按域拆开，避免并行写冲突。
