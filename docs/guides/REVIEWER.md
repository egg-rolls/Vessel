# 审查者须知

> **审查 PR / 合并前，必须先读完本文件。按顺序读，读完一项自检一项。**
> 跳过任何一项 = 审查遗漏，放行的 bug/违规会在未来引爆。

## 为什么必须先读这些

审查不是"看一眼代码对不对"——是验证代码是否符合架构约束、工程规范、安全红线。Vessel 有 10 条硬性门禁 + CI 四件套 + 反面模式清单。不读这些就审查 = 用直觉代替门禁，失去合并前验证的意义。

核心信条：**合并前验证，不合并后修复。**

## 必读清单（按此顺序）

### 1. CLAUDE.md（全篇）

仓库公共操作手册（~100 行，简短）。所有人必读。审查者重点关注 §4 红线。

**自检**：Vessel 的红线有哪些？

### 2. docs/specs/GIT-WORKFLOW.md（全篇）

分支模型、合并门禁（架构检查 + CI + 安全 + 回归确认）、审查流程、反面模式。

**自检**：§2.1 的 8 条架构检查清单是什么？§六的反面模式有哪些？

### 3. processes/collaboration.md

审查流程步骤、合并方式（Squash and merge）、分支清理。**知道审查的具体操作流程。**

**自检**：审查通过后如何合并？合并后如何清理分支？

### 4. processes/conventions.md

分支/Commit/Issue/PR 命名规范。**审查时检查命名是否合规。**

**自检**：PR 标题格式是什么？Commit type 有哪些？

### 5. docs/guides/DEVELOPER.md §代码设计纪律

审查时不仅看"功能对不对"，还要看"结构能不能扛住未来的变化"。读 DEVELOPER.md 中代码设计纪律一节，理解设计判断的视角。

**自检**：你能区分"硬性门禁"（binary check）和"设计判断"（需要动用判断力）吗？

### 6. docs/guides/DEVELOPER.md §能力分层 + CLAUDE.md §4 红线

确认新代码放对了层、没碰红线。

**自检**：core 只能因哪三种原因改？新增第二套扩展机制违哪条 ADR？

## 审查流程

```
1. 获取分支 diff
2. 对照下方硬性门禁逐条检查
3. 对照 DEVELOPER.md §代码设计纪律 + GIT-WORKFLOW.md §六 做设计判断
4. 检查硬编码密钥（grep）
5. 确认 CI 状态（lint/typecheck/test/build）
6. 输出审查结论（通过/阻断 + 原因）
```

---

## 硬性门禁（全绿方可合并）

```
[ ] 依赖方向：core 未引用 tui/config/plugins
[ ] 能力分层：新代码按 DEVELOPER.md 决策树正确分类
[ ] 红线：未触碰 CLAUDE.md §4 的任一条
[ ] 扩展机制：未新增第二套扩展路径
[ ] 事件类型：未用散落字符串替代 EventType 枚举
[ ] sync-in-async：异步路径中无同步阻塞调用
[ ] 半成品：无 NotImplementedError / 空实现进 core
[ ] 无硬编码密钥/Token/密码
[ ] 文档诚实：未声称未实现功能
[ ] 新能力：改 core 则必有 ADR
```

## 设计判断

读 DEVELOPER.md §代码设计纪律 + GIT-WORKFLOW.md §六 后做出判断：

- 新增代码的边界清晰吗？每个核心逻辑能**独立测试**吗？
- 加了新 case / 事件 / 工具——是只加不改，还是趟了一遍核心分发？
- 有没有**抄近路**的信号：超长函数、重复逻辑、散落魔法值、`as` 满屏飞？
- 这些信号是否有**有意识的设计决策**支撑？

**判断权在审查者手中**——信号是提醒多看一眼，不是阻断理由。但如果找不到解释，要求作者解释。

## CI 硬性门禁

```
bun run lint       → 必须通过
bun run typecheck  → 必须通过
bun test           → 必须通过
bun run build      → 必须通过
```

## 阻断规则

以下情况必须阻断合并：
- CI 任一项不通过
- 架构检查任一项不通过
- 发现硬编码密钥
- 分支有未解决的合并冲突
- "稍后修复"承诺——要求先修复再合

## 合并后

- GitHub PR "Squash and merge" 勾选 "Delete branch" 自动删除远程分支
- 确认 main push 成功
- 更新本地 main

---

## 审查后自检

- [ ] 所有硬性门禁都过了？
- [ ] 设计判断有依据（不是"感觉不对"）？
- [ ] CI 四灯全绿？
- [ ] 无硬编码密钥？
- [ ] 没有"稍后修复"承诺？
