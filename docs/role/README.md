# 角色文档体系

## 设计：双文件分层

每个角色有两个文件，分别对应 CLAUDE.md 和 AGENTS.md 的分工模式：

```
*-TODO.md      ← 执行清单（≈ CLAUDE.md，触发器）——含必读步骤 + 执行步骤
REQUIREMENTS-ANALYST / ARCHITECT / DEVELOPER / REVIEWER / DOC-MANAGER.md  ← 知识库（≈ AGENTS.md，详细说明 + 选读/按需参考）
```

**为什么分开**：AI 读完 300 行角色文档后，关键动作淹没在说明段落里，执行时漏步骤。TODO 文件 20 行纯步骤清单——AI 读到就能建任务列表，不跳步。执行中按需查详细说明。

**引用树（不跨层重复）**：`CLAUDE.md → role/XXX-TODO.md（必读，执行清单）→ role/XXX.md（选读/按需参考，知识库）`。每个角色 TODO 的前几步列出该角色开工前必须读完的文档（必读）；角色文档只保留核心内容（工程规范 / 硬规则 / PR 模板 / DoD）与"按需参考"表，不重复列出必读项。

## 根角色：CLAUDE.md + AGENTS.md

CLAUDE.md 是总 TODO——场景调度分发到各角色 TODO。AGENTS.md 是全局知识库——红线、能力分层、Core 冻结。根角色本身也遵循双文件分层逻辑。

```
CLAUDE.md（TODO）  场景调度
  ├── REQ-TODO.md  →  需求分析师
  ├── ARCH-TODO.md →  架构师
  ├── DEV-TODO.md  →  开发者
  ├── REVIEW-TODO.md →  审查者
  └── DOC-TODO.md  →  文档管理者
```

## 角色 ↔ 现实实体映射

每个角色关联一个现实软件工程实体——**激活 AI 对该实体的思维模式、能力边界和行为规范**，而非从空白状态推理。

| 角色 | 现实实体 | 核心思维 | 行为模式 |
|------|---------|---------|---------|
| **需求分析师** | Business Analyst / Requirements Engineer | "需求≠方案"——用户说的是方案，你要还原为问题 | 追问优先于写作：先理解为什么，再定义做什么。SPIN + JTBD 分层追问 |
| **架构师** | Software Architect / Tech Lead | "设计=权衡"——每个决策都有一个被否决的替代方案 | 拆解优先于实现：接口契约先行，正交拆分，假正交即退回 |
| **开发者** | Software Engineer | "代码=负债"——前期投入换长期回报，10 分钟设计停顿换 10 小时维护时间 | 规则优先于直觉：硬规则触发即纠正，不靠"感觉这样写更好" |
| **文档管理者** | Technical Writer / Documentation Engineer | "文档≠装饰"——不一致的文档是负资产，过期的文档是错误 | 规范优先于写作：先走链路再写，写完必自检 |
| **审查者** | Code Reviewer | "审查≠找碴"——查找将在未来引发事故的系统性风险 | 硬性门禁优先于设计判断，10 条逐项过，CI 不可跳 |

## 如何工作

### 两层 TodoList

CLAUDE 层只做调度，子角色层才处理用户需求：

```
CLAUDE.md（第一层 TodoList）
  1. 判断角色（对照场景调度表）
  2. 加载子角色 TODO → 用户需求插入到 [用户需求] 占位符
  3. 检查分支
  4. 按子 TODO 执行
      │
      ▼
子角色 TODO（第二层 TodoList）
  1. 读 AGENTS.md（全局约束）
  2. 读角色文档（工程规范 / PR 模板 / DoD）
  3. 读该角色直接依赖的流程/规范文档（collaboration / conventions / SPEC / ADR …）
  4. [用户需求] ← 用户的原始请求被插入到这里
  5. 处理需求（追问/预检/认领/走链路）
  ...
```

**占位符机制**：每个子 TODO 的 `[用户需求]` 步骤是 CLAUDE 层在加载子 TODO 时将用户原始请求填入的位置。用户需求不在第一层末尾，而在子流程的正确位置被处理。

### 执行
1. 按 TODO 前几步读完全部必读项（AGENTS.md → 角色文档 → 该角色直接依赖的流程/规范文档）
2. 必读项完成后，按 TODO 清单逐步执行，不跳步
3. 执行中需要深入 / 遇到决策点 → 回角色文档查"按需参考"表

**防淹没机制**：TODO 文件不超 30 行，始终在上下文中最前。角色文档在需要时才被完整加载——不让 AI 一次性消化 300 行然后自己去提取"我现在该做什么"。角色文档的"按需参考"表只列选读项，必读项不跨层重复。
