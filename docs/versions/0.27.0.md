## [0.27.0] - 2026-10-28

> 0.27.0（基于 0.26.2，未发布）：架构级重写——把三套并行执行事实收敛成一套统一
> agent/body 模型，并删除全部自动化测试。102 个 commit、5 个切片 merge、4 个 PR
> squash（#153 / #154 / #155 / #158）。未 tag、未 publish。

### Removed

三套并行事实是本版本的主体。它们不是「旧代码」，而是同一件事的三份各自可用的实现：
同一个 run 的口径、同一段串行语义、同一类生命周期事件，在各条路径上都不一样。

- **`RunEngine`（run 账本）**：`packages/serve/src/run-engine.ts`（1003 行）连同
  它维护的 run 队列 / live 视图 / 事件桥接整体删除。run 的 live 视图只剩 scheduler
  snapshot（tenant `InProcessScheduler`），durable 视图只剩每 body 的 `runStore`
  checkpoint；交互账本独立成 `interactions-registry.ts`。serve 因此不再持有执行队列、
  runtime 入口或 core run → job 映射，`runs.*` 经 `run-control.ts` 的端口接口由 app 侧
  注入（serve 不依赖 `@vessel-agent/agent`，分包方向不倒置）。
- **`RuntimeHost` / `InProcessRuntimeHost`（执行壳）**：`packages/core/src/kernel/runtime-host.ts`
  （1108 行）、`create-runtime.ts`（55 行）、`session-scope.ts`（39 行）与配套的
  per-body scheduler 契约删除。core 不再有第二套 host 层 loop 与 host 级 handle 代理；
  每个 body 直接持有自己的 `AgentRuntime`，串行由 `ScheduledTask.serialKey`
  （必填，等于 body / session id）在 scheduler 里表达。
- **owner / member 执行二分**：`src/agent-owner-injection.ts`（145 行）、
  `src/owner-runtime-facade.ts`（132 行）、`src/runtime-factory.ts`（193 行）删除。
  原先「root owner 注册外部 owner、父 turn 在 BeforeLlm 排空 owner 队列」这条第二入口
  不再存在，所有 agent（含 `main`）只经 `AgentService.admit` 准入。
- **测试**：仓库内 **483 个测试文件 / 96,662 行**全部删除（`packages/**/__tests__`、
  `apps/web/tests`、`src/__tests__`、`plugins/**/__tests__`、`scripts/__tests__` 与散落的
  `*.test.ts(x)` / `*.spec.ts(x)`）；17 个 `package.json` 的 `"test": "bun test"` 脚本、
  CI 的 11 处 `bun test` 调用（`ci.yml` 10 处 + `actions/quality/action.yml` 1 处）、
  `scripts/build.ts` 内部的 `execSync('bun test')` 一并移除。删因是设计问题而非覆盖率问题：
  `packages/agent/__tests__/team.test.ts` 手工构造 `agent.reply.posted` 事件喂给
  `TeamService`，绕过了已不再 emit 该事件的真实发射方，899 个绿灯因此漏掉了 Team 日志
  静默失效这类 P0。门禁改为 `typecheck` + `biome ci` + `scripts/check-*.ts` 静态断言，
  运行时正确性只靠一条端到端烟测（`VESSEL_MOCK=1 bun run src/cli.ts --run "hello"`）。
- **Team 配置**：`default_principal` / `handoff_path` 字段删除，改为结构化 policy 控件
  （`permission` / `budget` / `allowFork` / `federation`）；Web 侧提供 policy 表单而非
  自由文本字段。
- **执行生命周期事件**：`agent.turn.*` 与 `agent.reply.posted` 不再发射；`AgentEvent`
  不再携带回复正文。

### Added

- **统一 agent/body 模型**（[ADR-097](../adr/ADR-097-unified-agent-body-model.md)，accepted）：
  - 单一准入：`AgentService.admit({ agent_id?, session_id?, content, from, channel })` 是所有
    agent 的唯一入口；`main` 是普通 `single` agent（owner=self、无 Team、`private`），走
    普通 create 路径，与其它 agent 同一条准入、同一个 scheduler。
  - `body_id ≡ session_id`：一个 agent 可同时有多个 live body（每 agent ≤ 20，服务可注入
    覆盖；超限返回稳定错误 `body_limit`）；空闲 TTL 24h 自动 retire（0 = 关闭），primary
    被 retire 时提升最近活跃的 live body。
  - 同 body 串行、跨 body 并发（`perBodySerial`）；`maxConcurrency` 只有显式正整数才限制。
  - 每 body 独立 `AgentRuntime` / context / session 历史 / eventLog / `runStore` / plugin 实例。
  - `run.*` 是唯一执行生命周期，payload 带 `agent_id` + `session_id`；`agents.*` 条目对外
    暴露 `role`（`main` / `subagent` / `single` / `member` / `temporary`）。
- **快照 v4**：`bodies[]` 成为唯一真相（已退役条目保留 ≤50），`primary_body_id` 是缺省投递
  目标；`current_body` / `body_history` 降级为只读兼容视图。读取兼容 v1 / v2 / v3，
  v3 → v4 迁移首次写前备份 `.v3.bak`，失败则放弃本次写。
- **按段数寻址**（`packages/agent/src/team-address.ts`）：1 段 = 本机 agent（name 或 id，
  按查找阶梯）、2 段 = 本机 Team 内 agent（node 恒为本机）、3 段 = 跨节点。段数决定语义，
  不看「有没有 `@`」；`node` 段没有默认值，不会出现「本机冒充远端」。
- **来源行改为可回信的地址**：每轮注入 `<from location="principal@node:team" />` 自闭合标签，
  `location` 就是 `resolveAddress` / `send` 吃的同一形态，模型把该值原样填进 `to` 即可回信。
  本机来源也写满三段（`<from location="docs-core@a1b2c3d4:vessel-core" />`），不再教模型
  两种形态；无 Team 成员写两段，`nodeId` 缺省时退回两段（唯一允许的降级）。
  principal 段必须是可解析值：名字匹配 `[A-Za-z0-9_-]{1,64}` 用名字，否则写完整 uuid
  （不截断——解析侧只做精确匹配）。属性值转义 `&` / `<` / `>` / `"`。
- **保留 principal 词典**：`human` / `system` 不能当成员名或显式成员 id（`nameReserved`
  错误说明为什么），否则 `dispatch({to:'human'})` 会投给该成员、出站 `from` 被读成人类，
  跨节点身份静默丢失。新增保留名的唯一入口是 `RESERVED_PRINCIPALS`。
- **人类 principal 与 `main` 拆开**：消息缺省发送者是 `human` 而不是 `defaultOwner`；
  `defaultOwner` 只保留「临时成员归谁管」一个用途。`main` 因此受 conversation budget 约束。
- **重名复用**：同名成员已存在时 `create` / `hire` 返回已有条目并带 `reused: true`，
  不新建；该判定排在 `team_full` / `team_frozen` 之前。
- **成员名形状校验**：`^[A-Za-z0-9_-]{1,64}$`，错误消息说明允许的形状而不只是 invalid。
- **蜂群增长**：`agent` 工具新增 `create`（同 Team peer，要求调用者有 Team）与 `hire`
  （任意成员可雇 contractor，绑定调用者 Team 或 unbound）；每 Team present 成员 ≤ 20
  （`team_full`）；`teams.spawnFrozen` / `vessel team freeze|unfreeze <team_id>` 停止增长
  （`team_frozen`，`teams.update` 不改该字段）。close 审批：self / owner 关 contractor /
  root owner 直接 allow，成员关 peer 经权限 bridge 交人类审批，无 bridge 时 fail closed；
  owner close 级联关闭自己的 private contractor。
- **canonical 方法表 57 → 59**：新增 `permissions.setToolPolicy`（工具确认策略三档写回，
  CONTRACT-hot-apply §7）与 `teams.spawnFrozen`。
- **Web**：Tailwind v4 L1/L2/L3 分层（`@theme inline` 映射 `tokens.css`、不启用 preflight
  以保住现有视觉；legacy CSS 降入低优先级 layer）；`apps/web/src/components/ui` 通用组件层
  （Button / Badge / Field / Section / Stat / KeyValueList / DataTable / SearchInput /
  AutoGrowTextarea / `cn`）；zustand domain stores（agent / team / node / run / session /
  interaction / tenant / config / ui）；Team policy 表单、成员角色转换 UI、Team 聊天内应答
  成员权限；`scripts/check-web-styles.ts` 拒绝字面量 arbitrary value、class 字符串里的裸 hex
  与 inline style 颜色（`var()` 引用仍允许）。
- **TUI**：消费 `run.completed|failed|cancelled` 判定终态，并按 `session_id` 区分本轮流
  与其它 body 的轮（忽略其它 body 的 run 事件）——`run.*` 都带 `agent_id`，不能拿它区分。
- **`subscribe` 改为通知 + 显式 inspect**：订阅只发短通知，正文只在模型显式
  `subscribe inspect` 时返回，届时才推进 `seen_rev`；无 glob、无目录、无自动订阅。
- **文档结构门禁**：`docs/ARCHITECTURE.md` 2878 行拆成 `docs/architecture/` 的 20 个模块
  + `INDEX.md`（每个模块 ≤100 行，frontmatter 必填 `title` / `kind` / `triggers` / `paths`），
  新增 `docs/agents/` 7 篇按路径命中的领域告诫；`scripts/check-docs.ts` 校验 frontmatter /
  INDEX 覆盖 / 行数 / 相对链接 / current 文档不得带版本叙事；新增 `scripts/docs-find.ts`
  按目标检索。
- **`AGENTS.md` 精简**：226 → 84 行，只留身份入口、硬安全规则、核心架构红线与按路径命中的
  领域告诫；细节移入 `docs/architecture/` 与 `docs/agents/`。

### Changed

- `agents.create` 条目支持 `kind`（`peer` / `contractor`）与可选 `owner`；无 `kind` 的旧形状
  语义不变（按 temporary）。peer 必须有 `team_id` 且不接受 `workspace`。
- 可见性：private 成员的 id / 名字 / 回复不得进入 `from` / `to` / `mentions` / `content`；
  Team 成员强制权限 bridge，只有 human / policy 能应答。人类管理面 principal（`admin` 且
  无 `agent_id`）的 `agents.list` 合并无 Team 的 `single`（含 private single）。
- `runs.*` 不再由 serve 自持账本：`runs.start` 转成 `admit`，`runs.cancel` 直连 tenant
  scheduler，`run_id` 由 `admit` 生成。
- rotate 只退休 primary body：其它 live body 的历史 / checkpoint / epoch / 在途 run 不受影响；
  旧 body 的轮按自身 epoch fencing，发 `stale: true` 的配对终态，不写 state / usage。
- `scripts/check-rpc-methods.ts` 与 `docs/architecture/gateway-rpc.md` 的标记表格保持同源
  （59 项）。

### Errata（0.28 撤稿）

以下 0.27 的不变量在 0.28 被推翻，**原文保留**，以本段为准：

- **`role:'single'` 不存在了。** `AgentRole` 只剩 `'member' | 'temporary'`；`main` 是普通
  `member`，用 `kind:'peer'` + `workspace` 创建并属于某个 Team。本版「`main` 是普通 `single`、
  无 Team、`private`」的说法作废。存量快照里的 `role:'single'` 读取时降级为 `member`。
- **「一个 agent 可同时有多个 live body（每 agent ≤ 20）」作废。** 0.28 起一个 agent
  **恰好一具 live body**（`body_id ≡ session_id`），唯一例外是 `rotation === 'rotating'`
  期间的两具（新 + 待退役）。`liveBodies` 的多 body 语义、`maxLiveBodies`、body 级 TTL
  与 `trimRetiredBodies()` / `MAX_RETIRED_BODIES` 已删除；回收改为 agent 级、仅对
  `temporary` 生效，`bodyHistory` 上限 `MAX_BODY_HISTORY = 20`。
- **「人类管理面 principal 的 `agents.list` 合并无 Team 的 `single`」作废。** 不再有无 Team
  的 agent；`agents.list` 不再因管理面身份放宽 private 可见性。
- 可见性判定不再有「`role === 'single'` 时人类按 ADMIN_VIEWER 放行 private」这条特例。
- temporary 的缺省 `owner` 从调用方改为 `human`。
