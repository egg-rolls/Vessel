## [0.28.0] - 2026-10-29

> 0.28.0（基于 0.27.0，未发布）：Team 即工作区，会话即临时 agent。删 `single` role、
> 删多 body、agent 级回收与复活。17 个 commit、50 文件 +1836/−491。未 tag、未 publish。

### Removed

- **`single` role**：`AgentRole` 收敛为 `member | temporary`。`main` 变成普通成员，
  与其他 agent 走同一条准入、同一个 `create` 路径。存量快照里的 `role:'single'`
  读取时降级为 `member`（`snapshot.ts` 保留兼容分支，其余全仓无残留）。
- **一 agent 多 body**：`MemberRecord.bodies[]` 换成 `body` + `retiring` + `bodyHistory`。
  一个 agent 恰好一具 live body，唯一例外是 `rotation === 'rotating'` 期间新旧两具共存。
  快照文件格式不变（仍写 `bodies[]`，恒 1 项），旧数据读入时取 primary、其余降级进
  `body_history` —— 不在 parse 阶段 reject，否则整条成员连同其全部 session 一起丢。
- **`maxLiveBodies` / `bodyIdleTtlHours`**：body 级上限与 TTL 随多 body 一起删除，
  换成 agent 级的 `agent.temporaryTtlHours`（默认 2 小时）。

### Added

- **Team 即工作区**：打开一个目录就得到它对应的 Team（`workspace` 归一化后 slug，
  非 ASCII basename 走 `team-<hash>`，撞 slug 加哈希后缀且**绝不合并**）。headless
  不与目录绑定，同一 data root 至多一个合成 Team。
- **会话即 agent**：Web 的「新会话」不再是给 `main` 加一具 body，而是建一个临时 agent
  并把第一条消息发给它。TUI 同理，走同一条 `runs.start → admit` 链路。
- **临时 agent 回收与复活**：按 `max(record.lastSeen, body.lastActiveAt)` 判定，
  只回收 `temporary` 且 `present` 的 agent；`member`（含 `main`）永不回收。
  回收复用 close 语义（`membership='left'` + `state='closed'`），**body 记录保留**，
  复活时 unretire 并清 `body_history` 中该 session 的条目 —— 会话接得回来。
- **role 感知的上下文策略**：临时 agent 不自动压缩，到线只提示用户换会话。
  新增 `ContextManager.autoCompact` 只读 getter 与 `AgentRuntimeOptions.contextPressureHint`，
  二者都能在活体上热切换（`applyContextPolicy`）。**自动压缩关闭时压力提示取消 0.9 上界** ——
  否则 token 只会上穿阈值，提示永久静默。两道硬兜底（消息条数上限、provider overflow）
  对临时 agent 仍然生效。

### Fixed

- **`waitForConnectedRun` 的事件兜底从不启用**：判据要求 `runs.get` 「从未成功过」，
  而本地 member run 不写 durable checkpoint —— 运行中查询成功、终态后记录消失，
  兜底因此永久关闭，只能等超时。改为「查不到」与「不可用」同等对待。顺带修掉
  同 prompt 并发时误收其他 run 终态的问题：按 `job_id` 精确认领，一旦本 job 的 id
  已在候选中就不再退回猜测。
- **本地 REPL 绕过准入**：TUI 直连 `bundle.runtime`，会话不属于任何 agent，
  可见性 / 预算 / roster / role 策略全部对它无效。改走 `runs.start → admit`，
  与 Web、`--connect` 同一条链路。
- **飞书渠道在真实装配下起不来**：`channel.start()` 要求注入 `AgentService`，
  但渠道先于 `createAgentServiceWiring` 构造，该字段永远是 `undefined`。
  改为晚绑定 getter，`start()` 时求值。
- **飞书成员名非法**：`feishu:<chatId>` 含冒号，`MEMBER_NAME_RE` 直接拒绝 ——
  渠道成员建不出来。改为合法形状。
- **`slugifyWorkspace` 缺 `realpath` 与 NFC 归一**：软链与 macOS 的 NFD 会得到两个
  不同的 team id。
