## [0.33.0] - 2026-10-31

> 0.33.0（基于 0.32.0，未发布）：headless ask 异步、压缩质量、Web 尾部拆分、诊断 doctor 覆盖。
> 5 个提交、45 文件 +4045/−1996。未 tag、未 publish。

### Added

- **headless ask 异步**：headless / `--run` 现在注册 `ask_user`。提问时挂起 run 并持久化
  `StoredInteraction.suspended`，进程以 **exit 3** 退出（不挂死）；`vessel attention [--json]`
  可离线查看，`attention respond --answers` 应答，`vessel --resume-run <run>` 恢复并把答案作为
  `source=ask_resume` 的 user 消息注入。拒绝（`answers: []`）与超时路径有明确文案与事件。
- **压缩质量**：压缩前清空旧工具输出（保留最近 5 条原文、`tool_call_id`/name/assistant
  `tool_calls` 配对与全部 system）；摘要提示统一九段（目标/约束/已完成/进行中/阻塞/决策/
  相关文件/下一步/关键值），single / partial / reduce 三处一致。
- **诊断 page 覆盖 doctor --deep**：config / provider / data_dir / session / plugins / mcp /
  serve_port / attach / feishu_credentials 九类，固定顺序，每行标数据来源；RPC 拿不到的
  （config 校验、目录可写、端口 bind）标 `unavailable/info` 并写原因，不伪造。

### 已知边界

- 真实 provider 下的 ask 流程未跑（mock/fake 覆盖）；`--connect --run` 远端 ask 等待策略未改。
- `--serve --run` 与同进程 gateway 会双写同一份一致记录；离线 `attention` 无跨进程锁。
- 压缩保留区里被清空的旧工具结果，在 resume 从事件日志重放时会以原文重现（被压缩掉的不会）。
- `KEEP_RECENT_TOOL_RESULTS=5` 为模块常量，可按需调整。
