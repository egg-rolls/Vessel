## [0.19.0] - 2026-10-23

> 0.19.0（基于 `main`，**未发布**）：0.18 累积线（session liveness、workflow 移除、Web 设计系统、dev DX、update、interaction delivery）与 0.19 的 Agent/Body、Team、Hub、Web Team、权限/预算合并。未 tag、未 `npm publish`。

### Added

- **Agent / Body（S1）**：`<dataDir>/node.json` 持久化节点身份；成员快照 v2（配置 / `current_body` / `body_history`，读兼容 v1 + `.v1.bak`）；`membership` / `presence` / engine 三层状态；成员 engine 注入 tenant `SessionBackend` / `eventLog`；`AgentService.dispatch` 统一投递 + single-flight resume。
- **rotate（S2）**：新 Body 新 session + `epoch + 1`；spawn 成功后原子切 `current_body` 并 `flushSnapshot`，失败保持旧身体；旧轮 epoch fencing、`agent.retired`、80% 预警、权限按 Body session fencing。
- **Team（S3）**：按 workspace 分组的 Team、只写日志、`@` 定向投递、成员 A2A `send|list`、`post`、reply 日志、private 过滤、`reinstate`；canonical `teams.list/get/post/members`；成员侧 `agent` schema 扩为 `rotate|post|send|list`。
- **Hub（S5）**：app 层 `vessel hub start`；`/v1/hub/control` 目录 / 指针控制面；一次性配对与 `view/exchange/control/admin` scoped token；SecretStore；hub 不代理正文。
- **node → hub 出站（S5.1）**：`hub.direction: node`、`vessel hub join-code` / `vessel hub join`；hub 签发 `scope:'node'` token；`/v1/hub/node-control` 入站 + 节点出站 supervisor；双模共存；NAT 节点仅需出站。
- **Web Team（S6）**：独立 `team` 域、群聊、结构化 `@` 补全、成员侧栏、系统消息、`body_history`、`kind:'reply'` 内联、`online_count`。
- **权限 only-human + 预算（S4）**：删除死桥；`attachBridge` 是唯一活路径；`answered_by(human|policy)` 审计；ask 统一持久化并支持 duplicate/conflict/run_ended；默认 `hold`，team 可显式 `deny-after`；`conversation_id` 贯穿 dispatch / send / Team post / A2A / reply / rotate；team policy 上的 hops / turns / tokens / wall_clock 预算、双端检查、环检测、持久化 conversation 状态；canonical `teams.budget`。

### Changed

- **BREAKING（嵌入方）**：移除 workflow 产品面（插件 / CLI / TUI / Web / serve 方法 / 配置 / `/v1/workflows*`），canonical 减少 5 个 `workflow.*` 方法。
- **BREAKING（嵌入方）**：删除 `AgentService.requestPermission` / `AgentServiceOptions.permissionBridge` / `PermissionBridge`；唯一活路径是 `InProcessMemberRuntime.attachBridge` + `notePermissionState`。
- `agent` 工具的 `send` 切到统一 `dispatch`；成员动作变为 `rotate|post|send|list`，`new/close` 仍 owner-only。
- 成员快照写 v2；旧二进制不可读 v2（首次写前有 `<tenant>.json.v1.bak`）。
- 绑定 Team 且有名字的 Agent 默认 visibility 从 `private` 变为 `team`。
- canonical 方法表 **48**（40 + S3 4 + S5 3 + S4 1）；`teams.budget` 不进 team-scoped control scope。
- team-scoped control token 只能操作自己的 team；scoped `teams.list/get` 剔除 `workspace` / `handoff_path` / `policy`。
- `ask.respond` 的重复应答从 `not_found` 改为 duplicate / conflict / run_ended；权限/ask pending 在成员 turn 终态 / close 时转 orphaned。
- `vessel hub` 新增 `join-code` / `join`；`vessel team` 新增 `budget`；`hub.direction: node` 解锁出站。

### Fixed

- 0.18 累积修复：session liveness 崩溃后 stale running 对账；interaction 应答投递到 tenant runtime 流；Web 投影去重 / truncation / 断点增量；dev DX `bun run dev:web`；自更新通道与 beta 检查；Web 设计系统重做。
- P0：team-scoped token 跨 team 越权（`teams.get/post/members` mismatch → `not_found`，`teams.list` 只返回 own team）。
- Hub：吊销关闭 live WS、`incarnation`/`revision` 单调、`hub_id` 绑定、join 端点限流。

### Known limitations

- S7 跨节点 team ↔ team A2A / allowlist / hop budget；fork / `forked_from` 写入者：未实现。
- Web 预算 UI：S4 只提供事件 / RPC / CLI，Web 未渲染；TUI 只显示 notice。
- NAT 节点没有 `public_url` 时 `data_plane: unreachable`，正文需要隧道 / 反代；hub 不做中继。
- 一个 node 进程 / data dir 只加入一个 hub；node token 30 天过期后需要重新 join（无自动 refresh）。
- 重启保留预算计数 / override / blocked，但未消费消息队列仍只在内存；崩溃可能丢最后一个 debounce 窗口的 hop。
- only-human 是协议 / 工具面不变量，不是 OS 沙箱；同用户 shell 仍可能读本地 token。
- PR #133 的 Offline Integration 曾因 CI 引用已删除的 `plugins/workflow/engine` 而红，已由 #134 修复。

### 状态

- **S1 状态**：Agent / Body 内核 S1（分支 `0.19-s1-agent-body`，未随版本发布；版本 bump 待收口裁决）：`<dataDir>/node.json` 持久化节点身份（`host.nodeId` > 文件 > 首次生成，0600 原子写，损坏 `node_identity_corrupt` fail-fast）；成员快照写 v2、读兼容 v1，首次写 v2 前备份 `<tenant>.json.v1.bak`；状态拆成 `membership(present|left)` / `presence(live|gone)` / engine 三层，`stale` 降为只读 legacy，重启后非 `left` 一律 `idle + gone`；成员 engine 注入 tenant `SessionBackend` / `eventLog`，同一 `session_id` 跨进程续接历史；新增 `AgentService.dispatch`（live / rotating / gone / left + single-flight resume），strict `send` 错误码不变；名字只由 `present` 成员占用；`attachOwner` 是唯一 `left → present` 例外。S2 rotate / S3 Team / S4 权限与预算 / S5 Hub / S5.1 node → hub 出站 / S6 Web Team 见后续条目；**未实现**：fork、S7 跨节点（见个人侧 DECISION-035）。决策见 [ADR-091](../adr/ADR-091-agent-body-and-presence.md)。
- **S2 状态**：rotate 与 epoch fencing（分支 `0.19-s2-rotate` / `0.19-s2-docs`，未随版本发布）：`AgentService.rotate` 换一具新 Body（新 `session_id`、`epoch + 1`）：旧 Body 写 `startup_prompt`，新 Body spawn 成功后原子切 `current_body` 并 `await flushSnapshot()`，失败回滚并保持旧身体；rotating 期间 `dispatch` / `send` 排队；旧轮跑完后按 epoch fencing 成对发 `stale: true` 的 `agent.turn.*`（不写 state / usage、不投父队列）并发 `agent.retired`；`body_history` ≤20 落快照（仍 v2）；`entries` 按 session 键、`bySession` 跟随当前 Body；成员侧 `agent` schema 只暴露 `rotate`（S2 当时；S3 起扩为 `rotate|post|send|list`，见下一条）；80% 预警经 `onMemberEvent` 到达 Agent；权限回调按 Body session fencing。owner 端点 `agent.rotate` 与 CLI `vessel agent rotate` 已接线。决策见 [ADR-092](../adr/ADR-092-agent-rotate-and-epoch-fencing.md)。
- **S3 状态**：Team 基础（分支 `0.19-s3-team`，未随版本发布）：`packages/agent` 新增 `TeamService`（`list` / `get` / `post` / `members` / `send` / `listForCaller` / `subscribe`）；Team 元数据落 `<dataDir>/teams/<tenant>/<team_id>/team.json`，日志落同目录 `log.ndjson`（只追加、有界读、坏行跳过，不是队列）；`team_id` = workspace 目录名 slug，创建后不可变；roster 不单独持久化，由 Agent 记录的 `team_id + membership` 派生。无 `@` 的 post **只写日志、绝不 dispatch**；`@` 用结构化 agent id（不从正文解析），先写日志再逐条 dispatch；成员 `send` 同 Team 先写 `kind:'mention'` 日志，跨 Team / 无 Team 直接 dispatch。join / leave / rotate / archive 系统消息只写日志。绑定 Team 的 Agent 默认 visibility `team`，unbound 保持 `private`；private 成员 fail-closed，不写 Team 日志、不可被 `@`。`teams.members remove` 复用 `close` 归档，`add` 走 `AgentService.reinstate`（保留 `current_body` / `body_history`、不 spawn、`presence='gone'`）。成员完成一轮且 `team_id` 非空时写 `kind:'reply'` 日志并发 `agent.reply.posted`；`TeamSummary.online_count` 与 `TeamMemberSummary.body_history` 为派生 / 透传字段。canonical 新增 `teams.list` / `teams.get` / `teams.post` / `teams.members`。决策见 [ADR-091](../adr/ADR-091-agent-body-and-presence.md) 的 S3 Addendum。
- **S4 状态**：权限 only-human 与 conversation 预算（分支 `0.19-s4-permission-budget`，未随版本发布）：删除死桥 `AgentService.requestPermission` / `permissionBridge` / `PermissionBridge`，唯一活路径是 `InProcessMemberRuntime.attachBridge`；bridge 请求补 `team_id`，应答记录 `answered_by(human|policy)` / `answered_via` / `latency_ms`，ask 与权限统一持久化并支持 `duplicate` / `conflict` / `run_ended`；成员 pending 在 `agent.turn.*` / `agent.closed` 按 `agent_id + session_id` 转 `orphaned`。默认 `hold`，只有 team 显式 `deny-after` + `deny_after_seconds` 才自动 deny；无 `allow-after`、无全局 TTL。`conversation_id` 贯穿 dispatch / send / Team post / 本机 A2A / reply / rotate，Team log 保留；预算挂在 `teams[].policy.budget`（hops / turns / tokens / wall_clock，`max_cost` 不实现），状态落 `<dataDir>/conversations/<tenant>.json`（有界、原子、损坏 fail-closed、重启不清零）。canonical 新增 `teams.budget`（write，不进 control scope），总数 **48**。决策见 ADR-079 / ADR-091 的 S4 Addendum。
- **S5 状态**：Hub 控制面（分支 `0.19-s5-hub`，未随版本发布）：app 层独立前台进程 `vessel hub start`（`src/hub/`，不新增 package）；节点侧新增 `POST /v1/hub/pair` 与 WSS `/v1/hub/control`（协议 `vessel.hub/1`，帧带 `dialer`）；hub 侧提供 `GET /v1/hub/directory`、`POST /v1/hub/nodes` 与 `GET|DELETE /v1/hub/nodes/:pairing_id`、WS `/v1/hub/events`、`POST /v1/hub/data-token`。control / data plane 分离：hub 只维护节点目录并推 `{node_id, team_id, request_id?, reason, ts}` 指针，**不代理、不落盘正文 / 事件 / transcript**。一次性配对码换 `view` + `exchange` 两枚 token，节点只存 `sha256`，token 绑定 `hub_id`、可吊销；hub 的 token 走 `SecretStore`（DPAPI / Keychain / libsecret，Linux 文件回退需显式 `hub.allow_file_secrets`）。scope 为 `view | exchange | control | admin`，映射既有 `read / write / admin` rank；**team-scoped control token 只能访问自己的 team**（不匹配返回 `not_found`），`teams.list` / `teams.get.team` 的 scoped 响应剔除 `workspace` / `handoff_path` / `policy`。目录主键 `pairing_id = node_id:tenant_id`，上限 500 teams / 2000 agents（`truncated`）。canonical 新增 `auth.exchange` / `auth.revoke` / `auth.tokens`；S3 + S5 合并后总数 **47**，S4 的 `teams.budget` 加入后为 **48**（workflow 移除后 40 + S3 4 + S5 3 + S4 1）。S5 做 hub → node；node → hub 出站（NAT）由 S5.1 实现（见下一条）。决策见 [ADR-093](../adr/ADR-093-hub-control-plane.md)。
- **S5.1 状态**：Hub 出站加入（分支 `0.19-s5.1-node-outbound`，未随版本发布）：节点 gateway 配置 `hub.direction: node` 后主动拨号 `${hub.url}/v1/hub/node-control`，hub 作为 WS acceptor，只接受 `dialer: 'node'`；协议仍是同一套 `vessel.hub/1` 帧，节点可只监听回环、无需开放入站端口。hub 生成一次性 join code（`vessel hub join-code`，只存 `sha256`、默认 300 秒），node 执行 `vessel hub join <hub-url> --code` 换取 hub 签发的 `scope: 'node'` token（默认 30 天）；hub 只存 token hash，node 明文只进 SecretStore，非秘密状态写 `<gatewayDataDir>/hub-node.json` / `hub-node-status.json`；token 绑定 `hub_id` / `node_id` / `tenant_id`，不进 `PrincipalScope` / canonical RPC。目录补 `direction` / `public_url?` / `data_plane: direct|unreachable`（由 `public_url ?? url` 派生）；NAT 节点没有 `public_url`（隧道 / 反代）时正文不可达。陈旧快照沿用 `(incarnation, revision)` 判定与单连接接管；一个 node 进程 / data dir 只加入一个 hub；hub 仍不代理正文，现有 hub → node 行为不变，S5.1 不新增 canonical（S4 的 `teams.budget` 加入后总数 **48**）、不改 manifest。决策见 [ADR-093](../adr/ADR-093-hub-control-plane.md) 的 S5.1 Addendum。
- **S6 状态**：Web Team 群聊（分支 `0.19-s6-web-team`，未随版本发布）：`apps/web` 新增 `team` 域与路由（`#/team`、`#/team/<id>`、`/members/<memberId>`、`?body=<sessionId>`）；Team 列表 / 群聊 / 成员侧栏 / 成员详情 / Body 历史。消息来自 `teams.list|get|post`（HTTP RPC）；`@` 只从当前 Team `present` roster 补全并提交结构化 `mentions: [agent_id]`，正文里的 `@` 不解析；`kind:'reply'` 按 `message_id` 与轮询结果去重；`online_count` 直接用服务端字段，`body_history` 优先用服务端字段、缺失才回退事件观察；`waiting_permission` 映射为「等批准」。权限卡片仍在所属 `RunCard`，Team 只做 attention 徽标 + 跳转，不恢复全局遮罩。Web 只暴露 `teams.list|get|post`，成员 add / remove 仍走 CLI / owner 端点；Web 当前不消费 hub 目录 / data token。
