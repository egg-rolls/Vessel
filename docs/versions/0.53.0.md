## 一句话结论

0.53 把「模型看到的」与「用户看到的 / 磁盘上的」这两件事第一次拆成**可判定的两件事**：
落盘只能 append（C1 系列），请求视图的占位替换必须**有声明、有审计、集合逐条相等**才放行
（C1g 分档 + C1h 豁免裁定）；两者都不是灰度项。

## 变了什么

### 1. 上下文投射四模式（ADR-104 → 运行期）

- 词表 `passthrough` / `placeholder` / `externalize` / `archive_notice`，词表与冻结错误码见
  [ADR-104](../adr/ADR-104-context-projection-policy.md)；**默认 `placeholder`**
  （用户 2026-11-15 裁定，覆盖 ADR 原默认表里的 passthrough）。
- 声明：`SessionState.context_projection`（`declaration_id` / `source` / `policy` /
  `params` / `excluded_tools` / `declared_at`），**不可变**、子不能放松父；读侧唯一入口
  `resolveProjection`。
- 运行期：模式与「清哪些旧工具结果」都在 **run 起点冻结一次**（`windowProjectionMode` +
  `segmentClearPlans`），请求期只读；`passthrough` 与「完全没有投射机制」逐字节相同；
  未实现档运行期 fail-open 到 `passthrough` 并留审计（声明期降级落 `placeholder`，两层不混）。
- 审计：`context_projection_audit`（declaration + steps + reason + requested_mode + at），
  **只在决策变更的段起点写一条**。
- 归档：`archive_notice` 只登记不替换，追加归档卡 + `sessions.events` 按 `tool_call_id`
  读回原文；归档集合不进冻结集合（否则等于伪造「这批换成了占位」）。

### 2. trim 卡与占位幂等

- 折叠态标题只说**本轮新增**（`added` / `tool_call_ids`），展开明细给**会话内累计**
  （`cleared` / 保留条数）；同载荷（`cleared + added + fresh ids` 全等）不再 append、
  不重复发事件。
- `withClearedToolResults` 遇到已是占位的正文原样透传：占位文本的行数取自**原始结果**，
  把占位喂回去会退化成 `-> 1 lines`，每多投影一次多一层漂移。

### 3. 判据：C1g 分档 + C1h 按豁免事实裁定

- **C1g**：`passthrough` = 请求视图改写必须 0（带「同场景按 placeholder 会改 N 条」的反
  事实，防真空绿）；`placeholder` = 改写集合**恰好等于**「审计集合 ∩ 落盘工具结果」且每条
  都是占位；声明 / 读侧解析 / 请求期生效三者必须同模式。
- **C1h（本版收口）**：四真同时成立才 `EXEMPT` —— ① 声明存在
  （`placeholder|externalize`）② 审计行存在且链尾表达式与声明一致 ③ 审计集合 ∩ 落盘工具
  结果**逐条等于**实际改写集合 ④ 每条改写确实是 `isClearedToolResult`。任一不满足 ⇒ FAIL
  （错误行带 `mode=` / `audit=` / `request=`）。灰度机制 `pending()` 已删除；
  `--phase=1` 与默认模式结论必须相同。判据本身带 `C0b` 自检 10 例（缺声明 / 错模式 /
  缺审计 / 链尾不一致 / 缺集合 / 越界 / 漏改 / 非占位逐条立项），并真跑一遍真 EU
  （改 8 条 = 审计 8 条）。

### 4. 可观测与回放（前端第一次真读磁盘）

- `sessions.events` + `sessions.get.event_cursor`；环 1 万 → 5 万。
- 刷新/重连**两阶段回填**：阶段一 `sessions.events`（本会话日志）、阶段二 `events.list`
  （逐 `run_id` 拉 trace-only，最多 3 个 run）。只做阶段一在本机实测有
  767/847 = 90.6% 补不回。
- 观测面 `EventStore#diskBackfill`：累计位 + 最近一次快照（含 `stage1HitCap` /
  `stage1CapWarned` / `deferred` / `truncated` / `lastError`）。
- 跨源去重键 `stableEventId` 补 payload 摘要（不再吞同毫秒不同内容）；段内身份
  `(run_id, seq)` 保证跨次回填幂等。

### 5. 通知、可见性与工具名

- peer 成员停下真的能通知到父会话（创建者进程内映射 + `runtime.notice.injected`）；
  通知投递前重解析父 session（父在合并窗口内 rotate 也能落到新 body）。
- inbox 卡头补齐，可见性对等由 `check:env-scope-parity` 机械判定。
- `pii.reveal` → `piiReveal`（点号不是合法工具名）+ **注册期 fail-fast 校验**；老配置 /
  老会话的旧名换算表驱动（`ask_user` / `pii.reveal`），读侧双认、写侧只发新名。

### 6. 成员与历史

- `agent list includeReleases`（只读历史视图，默认 20 / 上限 200 / `fields`）；
  `closed_at` / `close_reason` 落盘（停用是终态）。

## 已知边界（交 0.54）

三条，均**不阻塞本次收口**、都影响「可证明不漏」的完整性，统一由 0.54 timeline 迁移兼并：

1. **chunk 不落盘**：`llm.stream.chunk` 磁盘两处都无，运行中的流式正文只能从环拿，
   重启即永久丢。
2. **三套 seq 无映射**：session 全局 / run per-run / hub 进程全局，跨源只能按内容 id 去重。
3. **trace-only 不交错**：`context.changed` / `hook.*` / `run.checkpoint` / `runtime.notice`
   只在 run trace，必须逐 run 作用域拉，不能用一个 `since_seq` 跨 run。
