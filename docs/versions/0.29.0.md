## [0.29.0] - 2026-10-30

> 0.29.0（基于 0.28.0，未发布）：prompt cache 的计量、命中率与压缩修复。
> 11 个提交、22 文件 +790/−42。未 tag、未 publish。

### Fixed

- **缓存开启后压缩不触发**：Anthropic 的 `input_tokens` 不含缓存读写，而压缩判断
  拿 `prompt_tokens + completion_tokens` 当真实上下文规模，于是只剩未缓存的残差 ——
  100k 的会话可能只报 5k。偏差正好等于缓存命中量，命中率越高错得越离谱。
  压缩永不触发，只靠 provider 报 400 后的溢出重试兜底，第二次溢出直接抛错。

### Added

- **`prompt_tokens` 语义统一**（U1）：所有 provider 的 `prompt_tokens` 现在都是
  「含缓存的全部输入」。Anthropic 的排他值由 adapter 补上两个缓存字段，OpenAI 原生
  已含则只提取 `cached_tokens`，DeepSeek 的拆分字段同样折叠。不报告缓存的 provider
  两个 cache 字段**缺省**（`undefined`），不是 0。
- **缓存计数贯通**：`UsageStats`、`run.completed` 事件、session 落盘、checkpoint 与
  **resume 恢复**都带上缓存数。`addTokens` 签名不变（可注入端口），计数在调用点直接累加。
- **聚合与展示**：`MetricsSnapshot.llm` 增加 `cache_read_tokens` / `cache_creation_tokens`；
  Web Observe 面板显示输入占比与前缀健康度；TUI 的 `/status` 与 run 收尾提示同样显示。
  比率是展示层派生量，不进快照。

### Changed

- **`inputTokensLimit` 会更早触发**：限额吃的是 `prompt_tokens`，语义统一后它含缓存，
  Anthropic 开缓存的用户从 5k 跳到 100k。这是统一的必然结果，不是缺陷。
- **跨版本 resume 偏差是单调的**：resume 把 checkpoint 的 `prompt_tokens` 整体按新口径
  读入再继续累加，长跑的 run 可能一跳顶到限额。

### Not building

- **不做计费 / 价格表**（ADR-005：不内置任何厂商 Key / 价格）。本版只到计数与比率，
  不产出任何金额。`totalCostLimit` 因此保持恒 0 —— 这是设计选择，不是缺陷。
- 不建模「最小可缓存阈值」（512/1024/2048/4096 分档会变，且 `0/0` 无法区分
  「低于阈值」「断点放错」「网络抖动」）。
- 不做 warmup 单列：依赖每请求谓词，而聚合量只有 `SUM`，`SUM(write)` 已丢失
  「写了几次」的信息，不可还原。
- 不新增 RPC 方法（复用 `metrics.get`）；不碰 TUI 状态栏（`PartKind` 是封闭联合，
  60–79 列会被丢弃）。
- `token` 限额与会话预算的底层口径（`limit-checker` / `conversation-budget`）
  未一并调整 —— 它们现在跟着 U1 自然变化，但没有单独设计。
