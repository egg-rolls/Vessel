# 消息不变量

> 两条**产品核心不变量**（2026-11-14 用户裁定）。违反任一条，宁可功能不做，也不要绕过。

## 1. 可见性对等

**UI 里用户看到的消息，必须包含会话中 agent 看到的全部消息。** 不允许「agent 知道、用户看不见」的信息不对称。

- 任何对模型侧内容的变形（脱敏、占位符、补充说明）都必须在用户侧**同样可见**；
- 「用户看到更多」只能来自**显式动作**（例如对真值做审批解锁），不能来自默认不对称；
- 推论：**存档 = 请求投影 = UI 列表**，三者逐字一致。任何"读侧滤镜"都违反本条。

## 2. 请求 messages append-only

**发给大模型的 messages 列表只能追加，不许修改中间任何一条。** 一旦改写中间内容，从改动点往后的整段 prefix 失效，**提示词缓存命中率被打掉**（长会话里代价极高）。

- 「引用已失效」这类状态变化 ⇒ **追加一条新消息**（环境信息卡，用户与模型同见），不许回改旧消息；
- 追加按 session 去重、只讲状态、**不含任何真值或片段**；
- 越界示例（**禁止**）：请求构造时把历史里的 `«pii:x»` 改写成 `«pii-expired:x»`；把历史中的原文替换成掩码；给旧消息补字段。

## 实现推论

| 事项 | 允许的做法 | 禁止的做法 |
|---|---|---|
| PII / 密钥脱敏 | 在**消息 append 的那一刻**落成占位符；真值留内存句柄仓库 | 请求构造时改历史；把真值写盘 |
| 真值获取 | 审批解锁（人批 + 一次性 + 审计） | 模型默认可见真值 |
| 引用失效 | 追加一条环境信息消息（去重、讲状态） | 回改旧消息 / 逐调用发卡片 |
| token 预算 / 上下文压缩 | **追加**摘要消息或新 run 的裁剪视图 | 改写既有消息内容 |

## 门禁

- 已有：`check:append-only-context`（落盘只追加）。
- 待补：`check:request-append-only` —— 断言「本次请求的 messages 是上一次的前缀延伸」（长度不减、逐字相同），任何中间差异必须红。
